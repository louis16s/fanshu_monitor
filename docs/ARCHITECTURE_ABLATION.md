# 架构消融实验

实验日期：2026-09-06

## 目的

验证当前架构中是否存在只增加维护成本、没有实际消费者的抽象。实验遵循小范围、可回退和行为不变原则，不重写现有功能链路。

## 基线

- Debug 单元测试：266 个测试，32 个测试套件，全部通过
- Release 静态分析：通过，无编译警告
- Release App：可以构建、签名并启动
- 当前硬件环境：本轮未连接可用的外接 DDC 服务，因此没有把真实 DDC 行为误判为已验证

## 消融候选与结果

### 已移除：`SystemCapabilityRegistry`

原实现包含一个带全局 `NSLock` 的能力登记表。锁屏和内建屏隔离桥接层只写入状态，生产代码没有读取方，只有一个测试读取它。因此它无法改变 UI、降级决策或恢复流程，却增加了全局状态、锁竞争和维护入口。

移除内容：

- 删除 `FanshuMonitor/SystemCapabilityRegistry.swift`
- 删除锁屏和显示器隔离桥接层的无消费者登记调用
- 删除只验证该登记表的测试
- 保留私有符号探测、统一日志和原有失败降级路径

对照结果：

- Debug 单元测试：265 个测试，31 个测试套件，全部通过
- `git diff --check`：通过
- 生产代码中无残留引用
- 预期收益是减少无效全局状态和两处失败路径的同步写入；当前没有足够证据宣称有可感知的 CPU 或内存下降

结论：删除安全，已纳入当前版本。

### 已移除：显示器硬件共享队列

`DisplayControlWorker` 原本在每块显示器自己的串行写入队列外，再同步进入一个没有状态、没有屏障的共享并发队列。每屏队列已经保证同屏读写顺序，共享队列没有提供额外隔离。

移除内容：

- 删除共享 `hardwareQueue`
- 原生亮度读取和控制写入直接运行在对应显示器的串行队列
- 保留跨显示器并行、同屏顺序、拓扑队列和发现队列

结论：该消融保留了现有队列语义，减少一次无效同步跳转和一个长期驻留队列，已纳入当前版本。

### 已简化：Codex 刷新间隔配置链

Codex 刷新间隔原先通过 `SamplingCoordinator` 的独立 setter 异步写入 actor，再由下一次采样读取。现在刷新间隔随采样请求传入；这样设置变更不需要额外任务，也不会出现配置任务和停用任务交错的窗口。限额重置时间也由同一次成功采样返回，避免从格式化文本反解析。

结论：保留 `SamplingCoordinator` 和 `CodexQuotaSampler` 两层，它们分别负责生命周期和有状态退避；只移除了重复的配置传递路径。

## 保留的抽象

- `SamplingCoordinator` 与 `MonitorModuleSamplerWorker`：负责采样器生命周期、取消、按模块串行化和按需驻留，不能合并回 View 或 Store
- `DisplayControlWorker`：负责 DDC/原生亮度的队列隔离、过期请求处理和拓扑恢复；删除会把硬件操作重新带回控制器
- `DisplayGammaHardware`：虽然生产环境只有系统实现，但测试需要假的硬件桥接来验证 Gamma 写入与恢复
- `DisplayControlDemandPolicy`、`MonitorSamplingPolicy`、`LockScreenAttemptRunner`：纯逻辑边界，有独立测试并减少系统事件与 UI 状态耦合
- `PreferencesCodec`：被多个设置迁移和持久化路径使用，统一错误日志；不是重复包装

## 暂不消融

`MonitorStore` 仍然偏大，但它是主线程状态汇聚点。将其继续拆分需要同时改动面板可见性、采样驻留、显示器需求和菜单栏状态，当前没有单一低风险消融切片。Codex 活动任务读取器的目录扫描也值得后续优化，但属于访问策略优化，不是删除抽象。

## 后续验证

需要在真实外接显示器、睡眠唤醒、显示器拔插和辅助功能权限变化下做回归，并使用 Instruments 对消融前后 CPU、内存和系统调用进行测量。静态消融结果不能替代这些硬件和性能验证。
