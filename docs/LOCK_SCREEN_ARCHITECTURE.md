# 番薯Monitor 锁屏架构

## 界面规则

- `系统锁屏设置` 必须是锁屏页面第一组
- 锁定方式放在该组第一行，当前方式为 `直接锁定`
- 自动锁屏状态条必须来自 `LockScreenPolicyStatus`，禁止在视图内拼接业务状态
- 恢复系统锁屏设置必须二次确认
- 常规页重置全部设置必须二次确认

## 控制边界

- `LockScreenPolicy` 保存时段、日期和闲置分钟数
- `LockScreenPolicyController` 只负责状态转换、一次性计时器和生命周期事件
- `LockScreenSystemBridge` 负责读取系统空闲时间、调用系统会话锁定服务、确认会话状态和读写系统屏保偏好
- `LockScreenSettingsView` 只展示状态和提交用户操作

## 状态转换

- 关闭策略时状态为 `disabled`
- 没有规则或不在生效时段时状态为 `noRules` 或 `waiting`
- 规则生效时状态为 `active`
- 到达闲置时间并发出锁定事件后状态为 `locking`
- 会话离开活动状态后状态为 `locked`
- 原生请求一秒内未确认时发送快捷键回退
- 主开关关闭不经过防抖，必须立即取消锁屏尝试；回退前再次确认策略仍然有效
- 八秒内未确认真实会话锁定状态时状态为 `lockFailed`，十秒后重试
- 普通解锁后立即重新计算；系统唤醒与会话激活合并为唯一的延迟恢复任务
- 策略关闭、系统休眠或应用退出时取消整个锁屏尝试，禁止延迟的快捷键继续执行

## 性能规则

- 锁屏使用一次性计时器，只在剩余闲置时间到达后校验
- 用户期间有输入时，只重新安排下一次剩余时间，不允许每秒轮询
- 辅助功能和输入监听权限只在启动、设置出现、应用重新激活或用户主动授权后检查
- 分时策略启用期间关闭系统空闲屏保，关闭策略时恢复保存的系统基线
- 策略生效且会话未锁定时使用 `PreventUserIdleDisplaySleep` 断言，避免系统显示器休眠先于直接锁定
- 断言在会话锁定、策略等待、策略关闭和控制器销毁时立即释放
- 休眠时取消计时和断言，唤醒一秒后重新计算，避免与系统唤醒流程竞争
- 应用正常退出时恢复系统屏保基线，但保留番薯Monitor 内的锁屏策略
- 每 60 秒校验一次屏保闲置值，防止系统设置或外部程序在策略执行期间改回屏保计时
- 屏保偏好写入必须检查同步结果并读回验证；电源断言失败必须在状态栏显示并低频重试
- 系统桥接通过 `LockScreenSystemEnvironment` 注入，控制器生命周期测试不读写真实系统设置
- `DirectScreenLocker` 只发送单次请求；延时、回退、取消和重试全部由 `LockScreenPolicyController` 统一调度
- 直接锁定优先动态调用系统 `SACLockScreenImmediate`，仅在系统符号不可用或未确认时回退 Control+Command+Q
- 锁定结果同时使用 `CGSessionCopyCurrentDictionary` 和工作区会话通知确认，禁止把事件投递成功当作锁定成功
- 锁屏时段的最终结束值不得超过 `40:00`
