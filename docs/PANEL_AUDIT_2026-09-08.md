# 面板算法、字体与消融审查

## 范围与证据

审查面板采样器、Codex HTTP 请求/转换/缓存、调度与 worker 生命周期、共享标题、详情网格及功率动画；检索显示器与锁屏的计时器和相关策略。本文不代表已完成所有真实硬件、权限及长时间睡眠唤醒验证。

基线提交：acb3694；本地备份分支：codex/backup-panel-audit-20260908。版本保持 0.3.2。

## Codex 差异

同一次检查中，本地持久化快照为 5H 剩余 90%、week 剩余 93%；HTTP 返回已用 27%/10%，应显示剩余 73%/90%。随后 Codex 应用接口返回已用 29%/10%，重置时间一致。检查期间任务持续耗用额度，两次请求不是同一时刻，因此不能把 2% 的变化归为计算误差。

确认快照时间不同是本次差异的因素；未观察到 100-used 换算反向或该账户的窗口错误。新增快照时间，标题悬停可读取更新时间；旧格式缓存提示等待刷新，失败保留数据并提供错误提示。请求明确传递 auth 中的账户 ID，并显式绕过 HTTP 缓存。当前账户传与不传该 ID 得到相同结果，账户头属于正确性补强，不是已证实的本次根因。

修复仅有周窗口时 module.value 为 0 而详情有值的问题，主值回退周剩余量。修复 Pro 被归一化成 Plus。中文和英文的周额度标签统一 week。

## 各模块算法

- CPU：用 CPU tick 差分计算系统、用户（含 nice）与闲置，归一到 0–100；第一次读取建立基线。零增量现在保留旧值。
- GPU：设备利用率与 Renderer/Tiler 是不同驱动字段，不相加；无总利用率时保留旧模块。
- UMA：使用页计数、内核页大小与物理内存计算；减去可清除/文件缓存页，限制结果范围。应用占用采用 phys_footprint。与活动监视器非同步采样不保证逐位一致。
- Power：遥测 mW 转 W；正电池功率表示充电，负值表示放电。优先直接系统功率，缺失才估算输入减电池功率。不同遥测字段可能不同步，不能用图形强行消除误差。适配器额定功率与实际输入功率保持区分。
- Codex：剩余为 100-used，限制到 0–100；窗口按时长识别，保留已有兼容兜底。成功快照和失败缓存现在可区分。
- Display：Gamma 使用基线表乘系数，限制到 0–1；本次未修改亮度映射、DDC 队列、熔断及恢复策略。真实显示器重启/拔插仍需硬件验证。
- 菜单栏组合指标是 CPU/GPU/内存压力加权产品指标，不是操作系统测得的总占用，保持现有权重。

## 字体

CPU、GPU、UMA、Power、Codex、Display 都使用 PanelModuleHeader：12 pt 系统字体、semibold、仅数字等宽。未发现模块绕过共享标题。详情网格是 10 pt 系统标签和 11 pt 等宽数值；功率分流为 9 pt 标签/10 pt 数值，设备徽标和辅助信息有单独层级。不是所有文本都应同一个字号。移除共享 caption 的 0.1 字距，使其符合零字距规范。

## 消融

PowerFlowAnimationPolicyTests.presentationAblationPreservesOutput 在同一 Debug 进程比较 10,000 组输出，三个指标各自重复构建 presentation 与一次构建复用的 checksum 完全相等。

- 重复解析：0.102928916 秒
- 一次解析复用：0.034747583 秒
- 该计算约减少 66%；不是整机 CPU 节省比例

保留 Core Animation/CAReplicatorLayer：它没有逐帧 SwiftUI Timer，能随充放电改变方向，支持减少动态效果。GIF 需要解码、独立状态资源与缩放，当前没有证据能获益，不引入。

相同输入/尺寸的路径更新现已跳过。移除粒子阴影的 GPU 收益没有实测百分比，不作量化声称。一次进程快照为 CPU 0.7%、RSS 297408 KiB；这不是稳定平均值，也没有可比的旧版基线。

## 刷新规则

MonitorRefreshSchedule、MonitorStore、Constants 无差异。0.8 秒面板采样、面板关闭降频、用户 Codex 周期、活动任务 2 秒、显示器刷新规则和 1.15 秒动画周期均保持。仅修正失败后重复到期调度的异常路径。

## 验证与后续

全量 271 项测试通过，Release analyze 通过。账户头、窗口换序/上下界、Pro、仅周主值、失败重置后退避都有验证；消融套件 4 项通过。Release 输出由 script/build_and_run.sh --verify 刷新并验证启动。

原生 UI 自动化读取超时，不能据此宣称浅/深色面板、动态流向均完成视觉验收。仍需同一时刻对照实际 Codex UI；网络失败继续显示最后一次快照，按照现有刷新间隔不可能保证两个独立应用每一刻都相同。

后续优先事项：将格式化字符串之外的数值/采样时间逐步保存在类型化模型中，避免解析显示文本；为缓存增加账户作用域，验证切换账户后的缓存隔离；活动任务日志的 120 秒停写判定可能误判长时间静默工具，应引入可验证的生命周期依据。以上不是本次已经完成的功能。
