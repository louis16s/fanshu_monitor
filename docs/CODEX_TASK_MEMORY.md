# Codex 活动任务读取的内存策略

## 容量与取舍

- 正向增量读取每块 256 KiB；保留原来的 2 秒任务刷新和 30 秒目录发现间隔
- 目录扫描过程中只保留修改时间最新的 12 个 rollout，时间相同时按路径排序
- 标题缓存最多 256 条；当前候选的标题优先保留，其余按索引更新顺序淘汰
- 淘汰的旧会话再次进入候选时，按需流式回查标题索引；没有匹配标题时记忆此次查询结果，后续索引追加仍能补齐标题
- 单条 JSONL 记录的缓冲上限为 1 MiB，超出后跳到下一条完整记录；普通生命周期和计划记录正常解析，超过上限的记录不解析
- 每块和每条记录使用局部 autoreleasepool，及时释放 FileHandle 与 JSONSerialization 产生的临时对象
- 索引截短后重建偏移、缓冲与标题缓存；取消读取后再次打开面板可以立即重新发现

保留小缓存能避免频繁开关面板造成反复读取。后台刷新规则、额度请求规则和任务超时规则维持现有配置。

## 模拟对比

2026-10-01 在本机以 Release 优化级别编译独立读取器，用同一组文件对比提交 `854672a` 与优化后代码：

- 12 个 rollout，各含 150 条约 20 KB 的工具输出记录
- 标题索引共 32,012 条，包含这 12 个当前会话的标题
- 两版均识别出 12 个活动任务，并保留正确标题
- 使用 macOS `/usr/bin/time -l` 记录峰值 RSS；重复运行排除首次启动耗时影响

| 读取器 | 峰值 RSS | 重复运行耗时 |
| --- | --- | --- |
| 原版 | 约 136 MiB | 0.24–0.26 秒 |
| 128 KiB 分块 | 约 11–12 MiB | 约 0.24 秒 |
| 256 KiB 分块 | 约 12 MiB | 0.23–0.24 秒 |
| 512 KiB 分块 | 约 13–14 MiB | 约 0.23 秒 |

这是独立读取器在上述模拟负载下的结果，不代表整个 SwiftUI 应用的内存降幅。选择 256 KiB 是为了控制峰值并保持合理的读取次数；128 KiB 的额外节省不足 1 MiB，512 KiB 没有显示出稳定的耗时优势。

## 回归范围

`CodexTaskProgressReaderTests` 覆盖跨块 UTF-8 与计划解析、超长未完成记录后的终态识别、标题缓存限额、旧会话重返与改名、索引重建、取消后的立即恢复，以及原有增量和超时行为。
