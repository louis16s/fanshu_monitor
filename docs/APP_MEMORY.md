# 应用内存策略

## 生命周期

- 面板与设置共用 `WindowResidentContent`，但使用不同驻留策略：主面板保留内容，点击时直接显示缓存读数，后台再刷新；设置窗口关闭时卸载内容，保留观察器和布局尺寸，重新打开时重建
- 主面板保留视图会占用一定内存，避免每次打开后等待视图重建的空白；面板关闭仍停止原有高频采样和动画，刷新间隔不变
- 打开面板时不重复同步未变化的调光开关；Gamma 读写、拓扑清理与恢复在后台串行队列执行，UI 线程只操作遮罩窗口。请求在状态锁内入队，保持清除、睡眠和后续亮度写入的顺序，遮罩更新检查请求代次
- 面板有效读数、折叠状态、设置页选择由外部状态层保存，不随内容卸载清空
- 窗口内容卸载不停止鼠标、锁屏或内建屏恢复服务；采样仍遵循既有需求与刷新规则
- 亮度遮罩不再使用时从字典移除，清空内容并关闭窗口，释放全屏绘制资源；所需亮度由服务状态保留，必要时重新创建遮罩
- Codex 活动任务的分块读取与缓存上限见 `CODEX_TASK_MEMORY.md`
- 采样器按需求释放的机制保持不变，不为了降低内存把有效缓存读数替换成零，也不增加写盘缓存

## 验证

`WindowResidentContentTests` 使用真实 AppKit 窗口连续开关三次，验证：

- 显示时内容挂载，隐藏时内容卸载
- 内容的 `StateObject` 弱引用归零，确认资源确实释放
- 隐藏和重新显示后布局尺寸保持不变
- 主面板驻留模式在窗口首次显示前已经挂载内容，反复开关保持同一内容对象，同时正确报告可见性变化

2026-10-01，本机 macOS 27、Release 的 `vmmap -summary` 记录：修改前已运行约 13 分钟的进程物理占用 85.7 MB；修改后新启动、未打开窗口的进程约 18.7 MB。这是不同运行阶段的观测，不能据此计算降幅，也不能作为长期占用承诺。

后续实测应使用相同设置、相同窗口开关次数与相同运行时长，对比 `Physical footprint`、峰值和窗口关闭后占用。RSS 与包含共享框架的 vmmap 总驻留值不代表应用独占内存。实际菜单栏面板在反复打开、关闭后是否存在短暂空白，以及长期运行、睡眠唤醒和真实显示器插拔，仍需持续观察。
