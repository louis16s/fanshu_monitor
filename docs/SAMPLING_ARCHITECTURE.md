# 采样架构

## 分层

1. `MonitorStore` 只负责 UI 状态、刷新调度和结果发布
2. `SamplingCoordinator` actor 管理采样器生命周期并隔离主线程
3. 每个 `MonitorModuleSamplerWorker` actor 独占一个模块采样器
4. `MonitorSampler` 只访问所属硬件或系统数据源

硬件读取不得直接放进 SwiftUI View 或 `MonitorStore` 的主线程回调

面板打开后，各个可见模块并发采样，任一模块完成后立即独立回填界面。不同模块不得因为慢速 I/O 相互等待；同一模块的状态与硬件访问仍由自己的 worker 串行保护

CPU 与 GPU 可以并发读取各自的轻量统计，但底层 SMC 调用使用共享锁串行执行，避免两个温度读取连接同时访问 AppleSMC

## 采样上下文

每次普通模块采样必须携带 `MonitorSamplingContext`

- `enabledMetricIDs` 表示用户实际启用的指标
- `panelVisible` 表示菜单栏面板当前是否打开
- 重指标必须同时满足指标已启用且面板可见

关闭面板时可以继续采集菜单栏圆环需要的轻量主值，但不得刷新 SMC 温度、SSID、IP、电池重遥测和外置卷等详情。再次打开面板时立即补一次完整采样

## 生命周期

- 隐藏模块后由 `SamplingCoordinator.retainSamplers` 释放对应 worker 和采样器
- 面板打开时调度器每 0.8 秒检查到期模块，CPU、UMA、GPU、网络使用 0.8 秒刷新，电源使用 2 秒刷新
- 面板关闭时调度器每 5 秒唤醒一次，只保留菜单栏圆环依赖的模块并使用降频间隔
- 网络在面板关闭时释放采样器并停止读取接口，只有菜单栏圆环明确选择网络时才保留轻量采样
- Codex 使用独立缓存和刷新间隔，并复用一个无磁盘缓存的网络会话
- 鼠标和显示器监听只订阅自身相关设置，不监听整个设置对象
- 鼠标连接状态由 IOHID 到达和移除通知驱动；没有匹配设备时停止事件 tap 和 HID++ 按钮监听，不使用定时枚举
- DPI 读取与写入通过单一串行 worker 执行，旧请求不得覆盖新状态

## 缓存规则

- 缓存必须属于对应采样器或设备实例
- 缓存应有明确有效期
- 面板关闭时保留最后一次详情用于避免界面重新出现时闪空值
- 手动或设备变更刷新可以清理对应缓存，不得清理无关模块

## 验证

修改采样架构后至少验证：

- 隐藏模块会释放采样器
- 关闭的重指标不会读取数据源
- 面板关闭时主调度器使用 5 秒间隔
- 面板打开后立即恢复详情采样
- 全量测试与 Release 静态分析通过
- 面板关闭状态下记录 CPU、常驻内存和线程数
